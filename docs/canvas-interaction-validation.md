# 画布交互优化与验证

验证日期：2026-10-19 至 2026-10-20。使用本地 Vite 应用及 Codex 内置浏览器，第一轮视口 873 × 885，第二轮 1280 × 720（包含全屏及普通工作台）。所有图表修改均在临时草稿中验证，未应用到用户文档。

## 交互依据

参考 draw.io 的平移、框选、吸附、快捷创建和目标反馈，以及 tldraw 的手势历史与相机规则。官方来源和采用理由见 [绘图工具交互参考](drawing-tool-references.md)。这是交互规则参考，不是与 draw.io 的 FPS 对比。

## 已解决的问题

| 问题 | 最终行为 |
| --- | --- |
| 选中对象或打开属性栏会重新适配，目标从鼠标下面移走 | 保持当前缩放和对象屏幕位置；节点、连线标签都补偿属性栏高度变化 |
| 双击消息标签，第二次点击落到空白而误建参与者 | 连线选择也保留点击位置，边标签输入允许鼠标定位光标而不失焦 |
| 小窗口打开长图时整体缩到难以阅读 | 初次打开至少 75%；F 主动查看全图，Shift F /“选区”聚焦所选对象 |
| 新增对象重叠、画布跳回中心 | 在当前可见区域附近避碰放置，只滚动到足以显示新对象的位置 |
| 单个、批量复制和用例专用入口的放置行为不一致 | 共用避碰与扩展规则，批量副本保持间距和内部连线；时序副本同步声明顺序 |
| Tab 快速创建方向错误 | 统一向右创建并连接，所有 11 个模板实测通过 |
| 拖动被固定边界截住 | 向右和向下按内容扩展，靠近视口边缘自动滚动；键盘微调采用相同边界规则 |
| 边缘按下轻微抖动也触发滚动 | 跨过拖动/连线阈值后才启动边缘滚动 |
| 关闭吸附仍被吸住，多选吸向自身组内对象 | 关闭吸附完全自由；Alt 临时绕过；排除组选中对象；吸附容差按屏幕像素换算 |
| 高频 pointermove 和滚轮缩放触发过多更新 | 按动画帧合并；保留稳定监听器；按已提交缩放计算锚点；松手刷新实际释放坐标 |
| 拖动让无关连线一起跳变 | 只使移动端点相关的线路失效；全量几何计算预先索引节点、并行边及时序行距 |
| 取消拖动/尺寸调整后历史被污染 | 恢复手势前的图、布局及 undo/redo；手势中撤销取消当前手势，不多撤销前一动作 |
| 取消改名清空旧 redo，又把取消文字放入 redo | 标签编辑使用独立事务快照，Escape 完整恢复原历史；输入法确认不提前提交 |
| 松手到空白仍连接到上一个悬停目标 | 仅按释放时实际命中的对象连接 |
| 非法连线静默拒绝 | 无效目标不高亮；自依赖、循环、重复依赖、状态起终点限制显示具体原因；完成、成功或退出后清除 |
| 时序增删和源码声明排序覆盖手工位置 | 按节点 ID 保留已有坐标，只补缺失位置 |
| 横向调整时序对象却冻结/拉长生命线，画布不断变高 | 左右手柄只改宽度，底部只改长度，角点改两者；隐式生命线不反向扩高画布 |
| 切换源码、模板、AI 页签丢失布局与历史 | 保持画布实例；只有选用新模板明确重建 |
| 源码暂时无效或编辑中间的部分图破坏原画布 | 草稿与已提交画布分离；返回画布时一次提交有效图，恢复原源码保留布局和历史 |
| 源码有效外部修改后，旧撤销覆盖新源码 | 保留坐标与缩放，同时清空旧画布历史，建立外部编辑边界 |

### 补充操作与数值

- 7 个支持多选的模板：Shift 选中两个对象，右方向键共同移动 1 单位；拖动后组内间距不变；复制得到两个副本，删除恢复原数量。
- 类图：空白框选两个对象，Shift 点击移除其中一个，选区适配显示 107% 缩放。
- 连续五次放大及五次缩小：79.3% → 129.3% → 79.3%；中心锚点误差分别约 0.020 / 0.132 个画布单位。
- 平移拖动 45 × 35 屏幕像素：scrollLeft / scrollTop 变化为 -45 / -35。全屏前后缩放保持一致。
- 流程图拖出旧边界：画布宽度从 1440 扩到 1706，边缘自动滚动；一次撤销同时恢复节点位置和 1440 宽度。
- 时序对象横向调整：174 → 224，画布高度不变，撤销回到 174；底部调整不改变宽度。
- 改名取消：先拖动再撤销，输入新名字后 Escape；原名字、原位置与此前 redo 均保留，redo 正确恢复拖动。
- 消息标签：双击进入编辑不再新增对象；鼠标点击输入框保持编辑；Escape 恢复原文，不产生 redo。
- 源码恢复：无效源码 → 临时有效部分源码 → 原源码，坐标、缩放和 undo 保持；有效修改标签后返回，坐标和缩放保留，旧 undo/redo 清空。
- 错误连接：状态 → 开始、结束 → 状态、思维导图成环、甘特重复依赖和循环依赖，显示对应原因；有效连接或 Escape 后恢复普通提示。
- 200 节点 / 199 连线图：新增第 201 个对象不改变原 200 个坐标；拖动和单步撤销通过，浏览器 error 日志为空。
- 纯编辑、纯预览、左右分栏：新图表均打开 6 节点初始图，75% 缩放；无修改时正常关闭。已有图表入口加载原文 8 个节点。关闭修改过的测试草稿需正常经过放弃确认。

## 自动检查与性能

- `npm run test:mermaid`：205 项通过，0 失败、0 跳过。
- `npm run typecheck`、`npm run lint`、`npm run build`、`git diff --check` 通过。

- 同进程 warm median，1000 节点 / 999 边：普通图全量连线计算 12.592 ms → 0.380 ms；时序图 25.619 ms → 0.150 ms。独立重复三次，新实现中位数分别为 0.390–0.412 ms、0.154–0.164 ms。

## 验证边界

实体触控板捏合、移动端多指手势、打包后的 Windows/Linux/macOS 原生 WebView 尚未逐平台实机验证。自动化输入无法可靠插入“鼠标仍按住时按 Escape/Ctrl Z”或系统 IME 候选确认：这些分支经过代码审查与事务/IME helper 回归，未冒充原生手势实测。Alt 相交框选及临时吸附绕过有逻辑回归覆盖，未记录实体修饰键拖动测量。

画布向右和向下自动扩展，左上仍保留边界。手工布局在当前工作台会话中保留，关闭后从 Mermaid 源码重新打开仍按算法布局；跨会话坐标持久化及大图虚拟化未纳入本次实现。未宣称达到固定 FPS，也未宣称全面等同 draw.io。
