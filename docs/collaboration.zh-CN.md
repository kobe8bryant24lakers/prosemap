# 多人协作编辑

ProseMap 默认编辑本地文档。打开 **共享此文档**，选择服务并确认后，服务才会用当前的文档名称和 Markdown 正文创建独立副本。离开会话即可回到原稿，保存本地原稿和导出共享副本是两个独立操作。

| 位置 | 谁运行服务 | 如何加入 |
| --- | --- | --- |
| 局域网服务 | 同一网络中的一台电脑，例如 Mac mini | 使用内网邀请链接。只需宿主运行服务，宿主离线期间编辑暂存于已打开的客户端。 |
| 远程服务器 | 云主机或公司 VPN 内的一台独立服务器 | HTTPS 邀请通过 WSS 同步，HTTP 邀请通过 WS 同步。最初发起共享的电脑可以关机。 |

## 在 ProseMap 中配置远程服务器

1. 打开 **设置 → 配置远程服务器**，输入管理员提供的完整 HTTP 或 HTTPS 地址。应用会检测该地址上的 ProseMap 协作服务。选择 **保存为默认服务器**，下次打开共享窗口会自动选中它。可以保存多个地址、切换默认服务器或移除地址，也可以先保存暂时离线的服务器。设备上只保存服务地址。
2. 分享者在本地文档中点击 **共享此文档**，确认服务在线，输入该服务的创建密钥，然后选择 **确认创建共享副本**。在 **管理邀请** 中复制编辑或只读邀请。只有确认创建时才会发出文档名称、正文和创建密钥。
3. 另一台电脑打开 ProseMap，点击工具栏上的 **加入**，粘贴完整邀请并点击 **加入会话**。应用使用邀请中的服务地址，来宾无需修改自己的默认服务器或提供创建密钥。编辑邀请可直接写作，只读邀请可阅读和导出。退出后回到原来的本地文档。

打开共享窗口、修改地址或粘贴邀请时，应用会通过实际同步连接检测服务是否在线以及服务模式是否匹配。检测不含正文、房间编号或令牌。窗口打开期间自动复查，也可以点击重新检测。网络恢复并显示在线后即可继续。对未提供检测功能的早期协作服务，仍可尝试已有的创建和加入操作。

远程 HTTP 会明文传输正文、创建密钥和邀请凭据，能观察网络流量的人可能取得它们。分享者和来宾均需在连接前确认。HTTP 适用于可信网络或受保护的 VPN，公网协作建议使用 HTTPS。桌面端可连接两种地址。在浏览器中连接 HTTP 服务时，直接打开该服务的 HTTP 页面或完整邀请链接。HTTPS 版编辑器仅连接加密的协作服务。

## 在 Mac mini 上启动

在含本功能的源码目录准备 Node.js 22.13 或更新版本，然后构建一次前端。浏览器来宾直接使用服务提供的编辑器，桌面来宾需要包含协作入口的构建。

```sh
npm ci
npm run build
```

将示例内网 IP 换成服务机的实际地址。以下命令显式开启**合成文档专用的明文测试模式**。同网可观察流量的人可能取得正文、创建密钥和邀请。真实文档应使用受客户端信任的 TLS 证书。

```sh
npm run collab:serve -- --mode lan --host 192.168.1.10 --port 8787 --synthetic-demo
```

单机演练可用 `127.0.0.1`。其他设备需要填写宿主的内网 IP。服务缺省绑定回环地址。`Ctrl+C` 停止服务，用相同地址和数据目录重启即可恢复。程序不会设置端口转发、防火墙规则或系统信任。

桌面端打开 **共享此文档 → 局域网服务** 时，会通过 Bonjour / mDNS 查找同一局域网内的 ProseMap 服务。如果本机默认地址离线、尚未指定地址且只发现一个服务，应用会填入该地址。多个结果可在列表中选择。回环地址和远程服务不会向局域网发布发现公告。浏览器、禁用组播的网络或使用自定义回环端口时，可直接填写服务地址。启动局域网服务时添加 `--no-discovery` 可仅按地址连接。

服务首次成功监听后，会在私有数据目录写入 `create.key`。局域网缺省目录为 `~/.prosemap/collaboration/lan`。可用 `--data` 指向持久目录。创建密钥仅供有权新建文档的人使用，普通来宾只需邀请链接。

已具备受信任证书时，可直接运行 HTTPS。证书的 SAN 须包含客户端输入的 IP 或主机名。下面是参数示例，证书文件由服务管理员提供。

```sh
npm run collab:serve -- --mode lan --host 192.168.1.10 --port 8787 \
  --public-url https://192.168.1.10:8787 \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

## 在云主机或 VPN 内部署

服务进程、前端构建、持久数据都放在独立服务器上。在服务器的 `/opt/prosemap` 准备此版本源码，执行 `npm ci` 和 `npm run build`。服务保留运行时依赖。站点根路径和 WebSocket 的 `/sync` 使用同一个域名和端口。

### HTTP 直连

将下面两处 `10.20.0.8` 换成服务器上实际可绑定、客户端经内网或 VPN 可达的私网 IP。也可以在 `--public-url` 中填写指向此地址的 HTTP 域名。此参数决定客户端填写的地址和邀请链接的协议。

```sh
npm run collab:serve -- --mode remote --host 10.20.0.8 --port 8787 \
  --public-url http://10.20.0.8:8787 --data ~/.prosemap/collaboration/remote
```

桌面端将同一个 HTTP 地址保存为默认服务器。分享者从指定数据目录的 `create.key` 取得创建密钥。服务重启时使用相同地址和数据目录即可恢复原有邀请与正文。使用下面的 systemd 配置管理 HTTP 服务时，将 `ExecStart` 中的监听 IP 和对外地址替换为实际值，保留 `--data /var/lib/prosemap-collab`。

已有 HTTP 反向代理时，可以让服务监听 `127.0.0.1:8787`，将 `--public-url` 设为客户端实际访问的 HTTP 地址，例如 `http://collab.example.org`。在 [Caddy 配置](../deploy/collaboration/Caddyfile)中将站点名写成同一个带 `http://` 的地址，保留 `reverse_proxy 127.0.0.1:8787` 即可转发编辑器和 WebSocket。其他代理也需保留请求的 `Host` 并转发 `/sync` 的 WebSocket Upgrade。

### HTTPS 与 WSS 反向代理

1. 将[服务配置](../deploy/collaboration/prosemap-collab.service)中的示例域名改成实际域名，确认 Node 可执行文件路径。`StateDirectory` 使 `/var/lib/prosemap-collab` 跨进程和主机重启保留，服务进程只监听 `127.0.0.1:8787`。
2. 将[Caddy 站点配置](../deploy/collaboration/Caddyfile)加入同机反向代理，使用相同的域名。代理须保留原始 `Host`，设置 `X-Forwarded-Proto: https`，并转发 WebSocket Upgrade。VPN 专用部署使用内部 DNS 和 VPN 网络监听地址，以及客户端已信任的证书。反代、DNS 和 TLS 由部署方管理。
3. 在目标服务器安装配置并启动。示例命令假定该机器已由管理员配好 Caddy。将站点块合入现有配置后再校验和重载。

```sh
sudo install -m 0644 deploy/collaboration/prosemap-collab.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now prosemap-collab
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

检查 `systemctl status prosemap-collab`。管理员可在服务器本机读取 `/var/lib/prosemap-collab/create.key`。在桌面客户端选择 **远程服务器**，填写例如 `https://collab.example.org` 的服务地址。HTTPS 地址始终使用 WSS，证书或连接错误不会触发明文重试。独立服务也可通过 `--cert` 和 `--key` 直接终结 TLS。

每个数据目录运行一个服务实例。在容器中运行时，将完整数据目录挂为持久卷。迁移时先停服，再复制整个目录，包括 SQLite 文件、日志文件和创建凭据。恢复这个目录可保留所有者权限和仍有效的邀请。

## 创建、加入和恢复

1. 发起者打开本地 Markdown，点击 **共享此文档**。选择服务位置，填写服务地址和创建密钥，核对文档名称后点击 **确认创建共享副本**。明文局域网还需确认使用合成内容。
2. 在 **管理邀请** 中生成 **编辑邀请** 或 **只读邀请**，复制链接给对应来宾。两种邀请独立，有效期均为 24 小时。同一面板可复制 **所有者恢复链接**，私下保存以便以后管理这份文档。
3. 来宾可在浏览器打开链接并点击 **加入会话**，或在桌面端的 **加入** 入口粘贴链接。只读来宾可阅读和导出。服务端校验每次正文写入和邀请管理操作。
4. 在同一段落输入时，远端光标和选区会显示在 CodeMirror 中。服务持久写入后显示 **已保存到服务器**。离线编辑保留在当前打开的窗口，自动重连后合并。关闭前应等到保存确认，或先 **导出 .md**。
5. 撤销某类邀请会断开使用该链接的在线来宾，旧链接随即失效。已发送到设备的内容和已经导出的文件仍归其持有。所有者可生成新链接继续协作。

每次共享的正文上限为 2 MiB。共享预览支持 Markdown 和 Mermaid 源码渲染。包含外部资源或自定义配置的图表可在源码栏查看。相对路径附件、原始 HTML 资源、AI 上下文、模型配置、对话和本机文件夹均不随副本传输。AI 改写和画布写入只在本地文档提供。导出默认使用 `-shared.md` 文件名，原生导出要求选择新文件名。

## 复现验收

在已安装 Node.js 和 OpenSSL 的测试机运行以下命令。测试创建临时数据目录和临时证书，使用合成正文。Chromium 的证书许可仅限本次测试进程和测试证书的公钥，系统信任设置无需更改。

```sh
npm ci
npx playwright install chromium webkit
npm run test:collab
```

测试通过真实构建的前端创建副本，从独立客户端加入，检查同段合并、在场光标、断线重连、服务重启、只读写入拒绝、撤销与过期、跨房间隔离和导出。两组远程用例分别使用 HTTP/WS 和 HTTPS/WSS，两组均在局域网进程停机后继续编辑。这是隔离进程验证，跨物理网络和 Windows 设备需要分别实测。

如需把同一套验收放到 Caddy 反代之后，设置 `PROSEMAP_TEST_CADDY` 为 Caddy 可执行文件的路径。另可用 `PROSEMAP_TEST_LAN_HOST` 指定测试机的实际内网 IPv4 地址。测试使用短时端口和单独的数据目录。

```sh
PROSEMAP_TEST_CADDY="$(command -v caddy)" npm run test:collab
```
