# ProseMap v0.11.1

This desktop preview release improves file recovery, Mermaid source preservation, canvas editing and fullscreen readability. It is published with known acceptance gaps; it does not claim that all native workflows have passed.

## Changes

- Preserve the actual file version displaced by a concurrent save. If it differs from the expected disk contents, retain a visible Markdown recovery copy, show its path and keep the editor's changes unsaved. Save As to a new path does not overwrite a file created concurrently, and the saved baseline uses the content actually committed.
- Preserve Mermaid comments, declaration order, indentation and LF/CRLF/mixed line endings through supported label, member and structural edits. Improve class/ER member-block recognition, nested Markdown fence targeting and document/canvas undo boundaries.
- Keep diagram selection, property panels and history consistent through object creation, deletion, duplication and layout. Correct group containment, connected-node placement, flow markers, ER cardinalities and sequence interactions.
- Protect unapplied drafts when closing or replacing diagrams. Keep keyboard actions and focus inside dialogs, preserve rejected label edits and ignore stale formatting, preview, AI and file-selection results.
- Keep Markdown editor and preview scrolling aligned by source blocks, including documents with images and diagrams. This is block-level interpolation, not exact line-by-line pixel alignment.
- Apply a readable minimum zoom to fullscreen diagrams, targeting at least 12 CSS pixels for rendered text. The separate **Overview / 一屏总览** button fits the complete diagram even when labels must be smaller; percentage reset or zooming in returns to the readable view.
- Improve native open-error feedback, clipboard feedback, model-loading recovery and dialog cancellation. Development builds use a separate app identity and session-only model credentials; those builds are not production release packages.

## Validation

- The latest complete local candidate-84 interaction run passed **2,214/2,214** checks: 1,107 each in Chromium and WebKit, with no failures, skips or flaky results. Browser tests substitute native IPC and external services and do not replace desktop acceptance.
- The publication checks passed **542 frontend logic tests**, **55 Rust tests with the production credential backend**, ESLint, TypeScript and deterministic fixture verification. The candidate-84 development backend also passed 57 Rust tests. The release workflow runs automated checks against the tagged source before building installers.
- Native macOS validation used synthetic documents. It includes all 11 diagram templates, label and structural edits across four line-ending variants, readable fullscreen/Overview controls, and real save-conflict recovery with concurrent filesystem replacements. Windows and Linux installer smoke tests remain outstanding even when their packages build successfully.
- The **494-item acceptance matrix remains incomplete**: 378 passed, 3 partial/unresolved, 104 limited by the available tools or environment, and 9 unsupported. Historical failures and their original evidence are retained locally; later successful controls are not recorded as explanations for those failures.

See the [acceptance matrix](../v0.11.0-deep-acceptance.md) and [coverage audit](../v0.11.0-acceptance-audit.md).

## Known gaps and boundaries

- **APP-10:** a historical external invalid-UTF-8 open produced no observed error event or notification. Current controls pass, but the original handoff's cause remains unresolved.
- **FILE-01:** the native macOS Open button previously remained disabled after selecting and reselecting an existing Markdown file. Current controls pass; the historical picker state remains unexplained.
- **C07:** a historical 100% canvas-reset screenshot placed a selected node away from center, while a separately collected Inspector sample showed centered geometry. Current and archived binaries now show centered captures; synchronized historical evidence and independent physical-screen confirmation remain unavailable.
- Some physical pointer/trackpad gestures, genuine Chinese IME composition and system credential prompts could not be reliably exercised by native automation. These are not counted as passing.
- Save recovery preserves the version displaced at commit time. It is not a cross-process filesystem compare-and-swap and does not prevent later external writes or writes through an already-open descriptor to the displaced file.
- Arbitrary or ambiguous Mermaid declarations may require canonical serialization. Manual layout remains session-local. Document/session restoration, an outline and image export remain outside the implemented scope recorded in the matrix.

## Downloads and signing

Successful release jobs attach Windows EXE/MSI, Linux DEB/AppImage and platform SHA-256 checksum files. These packages are unsigned; compare each download with its corresponding checksum file.

A production macOS universal DMG requires a configured **Developer ID Application** identity and certificate. That signing configuration is currently unavailable, so a macOS v0.11.1 installer is not promised by this release. The workflow must retain its signing requirement; an ad-hoc, self-signed or memory-only development app must not be substituted for the production Keychain build. Existing macOS releases remain available on their own release pages.

Build availability is determined by the assets actually attached to this release. Packaging success does not constitute native installation acceptance or notarization.
