# ProseMap v0.11.1

This patch improves Markdown preservation, canvas history and document safety. Deep native acceptance is still in progress; the matrix records verified paths and remaining gaps separately.

## Fixes

- Keep the original spelling, comments and formatting of supported Mermaid edits through canvas undo/redo. Locate diagrams inside lists and quotations by their Markdown syntax, including repeated diagrams.
- Start a new canvas history boundary after an external source edit, so earlier graph snapshots cannot restore an obsolete spelling. Preserve existing fence markers, whitespace and container syntax when applying a diagram back to Markdown.
- Keep class and ER member edits inside their original declaration blocks, including repeated field names; preserve unrelated declaration order and comments. Undo and redo retain still-existing selected objects and keep their property panels available.
- Preserve the model’s leading indentation, trailing spaces and final newlines in accepted prose suggestions; whitespace-only responses remain invalid.
- Publish completed AI drafts to the currently visible canvas before subsequent manual edits, and ignore late AI results after the user edits the diagram.
- Use consistent editor and preview coordinates for CRLF files. Preserve existing LF, CRLF and mixed line endings during editing, language changes, saves and history; apply separate changes without rewriting the text between them. Opening another document starts a separate undo history.
- Reject saves when the disk file has changed externally. Reload from disk with an explicit confirmation before discarding local changes, or use Save As to retain both versions.
- Distinguish Save, Save As and Open shortcuts. Keep modal focus and keyboard actions inside the current dialog and return focus on close.
- Keep quick creation from also selecting or dragging the canvas. A stationary pointer release no longer snaps a node or adds a history entry, and a final queued drag position is retained.
- Restore the last editor/preview/split mode, recover heading navigation after an invalid anchor, and display accurate clipboard and unsupported remote-image feedback.
- Show feedback while system model settings are loading, allow the dialog to close, and offer retry after errors without exposing an editable empty profile collection.

## Verification

- Candidate 10 passed 383 frontend logic tests and 30 focused Chromium/WebKit interaction tests locally. That assertion has been corrected and all 36 gesture tests pass; the final full CI batch remains required before release. Browser tests substitute native IPC, credentials and AI responses; they are not native desktop acceptance.
- 38 Rust tests passed, including real-file external modification and atomic save checks. Lint, TypeScript, fixture verification and the macOS candidate build passed.
- Installed macOS candidates were exercised with synthetic files. Evidence includes the 11 diagram types' basic editing chains, CRLF and mixed-line-ending saves/history, nested diagram targeting, external file recovery, Save As destination changes, unsaved-close protection, class-member editing, genuine filesystem write-error recovery and fence whitespace/history. Candidate 10 also passed all 16 ER field assertions, including exact file bytes, persistent selection through history and reopening the saved document after process exit.
- The repository includes a 494-row acceptance matrix, deterministic Markdown fixtures, an 8,406-line document, 300-node and over-limit diagrams, and a CI workflow that gates release builds on automated interaction checks.

See [the acceptance matrix](../v0.11.0-deep-acceptance.md) and [remaining coverage](../v0.11.0-acceptance-audit.md). These records do not claim all 494 native acceptance rows are complete.

## Remaining limitations

Physical pointer/trackpad gestures and genuine Chinese IME composition remain unverified in the available native automation. Candidate 10 model settings remain pending in the local credential load, so live AI whitespace preservation has only browser coverage so far. Full native model/keychain success and failure paths, every diagram-specific interaction, and cross-platform installation still require completion. Source preservation falls back to canonical Mermaid for ambiguous declarations; arbitrary Mermaid text is not guaranteed byte-for-byte preservation. Last-file, cursor, scroll and unsaved-session restoration, a document outline and image export are not implemented. External writers do not share the application's save lock, so the final disk check is not a cross-process compare-and-swap.
