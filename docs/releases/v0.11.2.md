# ProseMap v0.11.2

This desktop preview fixes Mermaid generation being rejected with an unsupported-HTML error when the model returns ordinary line breaks or supported diagram declarations.

## Changes

- Both the document AI assistant and diagram workbench now use the same safety checks and generation guidance. Attribute-free `<br>`, `<br/>` and `<br />` line breaks are accepted, including uppercase variants, while the generated source is preserved.
- Recognize the common class annotations `<<interface>>`, `<<abstract>>`, `<<service>>` and `<<enumeration>>`, and state declarations using `<<choice>>`, `<<fork>>` and `<<join>>`. These exceptions apply to complete declaration lines in the matching diagram type, rather than arbitrary text inside labels.
- Continue rejecting other HTML tags, line-break attributes, clickable directives, initialization directives and JavaScript URLs. Mermaid strict rendering and SVG sanitization remain enabled. The error message explains which line-break syntax is supported.

## Validation

- Local regression passed **38 Chromium/WebKit checks**, covering both generation entry points, actual multiline rendering, exact apply/save results, unsafe-source rejection and preservation of the original document. The two entry points both reproduced the original failure before the fix.
- **573 frontend logic tests**, ESLint, TypeScript and the production frontend build passed. Model responses and native IPC are synthetic in browser tests; these results do not prove real model-service or installed-desktop behavior.
- The release pipeline runs the complete browser acceptance suite against the tagged source before building installers. Packaging results and available downloads are determined by the actual release jobs and attached assets.

## Known limits

- The added annotation recognition is deliberately limited to the declaration forms above. Custom annotations, multiple declarations on one line or trailing comments can still be rejected. This release does not claim complete Mermaid syntax support.
- The existing **494-item native acceptance matrix remains incomplete**: 378 passed, 3 partial/unresolved, 104 tool-limited and 9 unsupported. Historical APP-10, FILE-01 and C07 findings remain unresolved. The earlier intermittent Linux WebKit automation timeouts are not claimed fixed by this patch. See the [acceptance matrix](../v0.11.0-deep-acceptance.md), [coverage audit](../v0.11.0-acceptance-audit.md) and [previous release limitations](v0.11.1.md).
- Windows and Linux installer smoke tests remain outstanding. A successful package build is not native installation acceptance.

## Downloads and signing

Successful jobs attach Windows x64 EXE/MSI and Linux x64 DEB/AppImage packages with platform SHA-256 checksum files. These packages are unsigned.

The production macOS build still requires a **Developer ID Application** certificate. That signing configuration is unavailable, so a macOS v0.11.2 DMG is not promised. The signing requirement remains enabled; a development or ad-hoc build is not substituted for the production Keychain build.
