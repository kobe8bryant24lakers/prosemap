# ProseMap v0.12.1

This desktop preview improves Markdown indentation, sequence-message placement and Mermaid preview navigation.

## Changes

- Add **Increase indent / 增加缩进** and **Decrease indent / 减少缩进** to the Markdown toolbar. Reuse CodeMirror's two-space indentation rules, retain selection and focus, and make each button press separately undoable.
- Insert a new sequence message at the timeline position shown by its drag preview instead of always appending it. Preserve message order through canvas/source round trips, retain existing control directives, comments, indentation and line endings, and support undo/redo.
- Support direct mouse-wheel zoom and canvas dragging in inline Mermaid previews. A stable viewport lets users pan to areas clipped by zoom. Fullscreen previews share the pointer handling while retaining readable zoom limits and existing zoom/reset controls. Double-click editing and scrolling outside the diagram remain available.

## Validation

- **594 frontend logic tests** passed locally, including 17 sequence-insertion cases for nested blocks, branches, duplicate/self messages, reordered/deleted messages and LF/CRLF source preservation.
- **132 Chromium/WebKit interaction checks** passed locally: 66 per browser. These cover selection, indentation, independent undo, sequence insertion and both histories, preview wheel zoom/panning, actual clipped-node visibility, double-click editing, body scrolling, full-screen readable limits and marker rendering.
- ESLint, TypeScript and the production frontend build passed locally. The build emits a bundle-size advisory.
- Browser checks use identifiable synthetic documents and simulated desktop IPC. They are not installed-desktop, real-filesystem or physical-input-device acceptance. See the [implementation validation record](../queued-editor-polish-validation.md).
- PR and tag workflows run the full browser acceptance suite. Installer availability depends on successful packaging jobs and attached release assets.

## Known limits

- Sequence canvas placement uses message rows rather than separate directive rows. Insertion before a message uses that message's existing control block; the final slot appends after closed blocks. Empty-block placement and exact placement on either side of an intervening directive still require source editing. Unsupported visual syntax retains the existing source-only behavior.
- The historical **494-item native acceptance matrix remains incomplete**: 378 passed, 3 partial/unresolved, 104 tool-limited and 9 unsupported. APP-10, FILE-01 and C07 remain unresolved. Historical Linux WebKit automation timeouts are not claimed fixed. See the [acceptance matrix](../v0.11.0-deep-acceptance.md), [coverage audit](../v0.11.0-acceptance-audit.md) and [previous release limitations](v0.12.0.md).
- Windows and Linux installer smoke tests remain outstanding. Successful packaging does not establish native installation acceptance. This release does not repeat historical native acceptance or replace an installed application.

## Downloads and signing

Successful jobs attach unsigned Windows x64 EXE/MSI and Linux x64 DEB/AppImage packages with platform SHA-256 checksum files.

The production macOS build still requires a **Developer ID Application** certificate. That signing configuration was unavailable for the preceding release, so a macOS v0.12.1 DMG is not promised. The signing requirement is unchanged; a development or ad-hoc build is not substituted for the production Keychain build.
