# ProseMap v0.13.0

This desktop preview adds local project context, multi-turn editing conversations, and automatic model-generated history summaries for Markdown and Mermaid.

## Changes

- Select a locally cloned repository or reference folder, search relative file paths, and choose files shared by the writing assistant and diagram workbench. Selected project files are read again before each generation. Nested `.gitignore` rules, file bounds, and link restrictions are checked before reading.
- Continue refining Markdown suggestions without applying them, inspect prior generated content, and distinguish proposed, accepted, and rejected changes. Diagram conversations use the current workbench draft, including manual edits.
- Automatically summarize older exchanges when the next request would exceed its history budget. Carry previous summaries forward with recent complete turns and the latest document. The summary explicitly requests goals, constraints, decisions, rejected alternatives, and pending work; it remains historical reference data.
- Inspect the summary and its covered-turn count. Starting a new conversation clears both memory and recent turns. Failed, cancelled, and stale compression never commits a partial summary or silently drops history to continue an edit.
- Show actual reference truncation and compression progress, preserve precise context-read errors, and isolate pending reads and model responses from replacement documents.
- Update DOMPurify to 3.4.18, including the available security fixes for the previously installed 3.4.14.

## Known limits

- Reference files must be selected explicitly. Remote cloning, repository-wide autonomous exploration, indexing, and shell execution are not included. Folder scans are bounded to 2,000 files, 20,000 visited entries, and 12 directory levels; incomplete scans are identified. Hidden files, common generated/dependency folders, and credential-like names are excluded; these filters do not inspect code for embedded secrets.
- Up to 12 UTF-8 files may be selected across attachments and project context, with a 2 MB per-file limit. Reference content is capped at 80,000 characters and may be reduced further. Individually attached files remain selection-time snapshots; only folder-selected files are reread per request.
- Compression uses the selected model, adds requests/latency/provider costs, and is lossy. Summaries are limited to 4,000 characters; recent turns and the summary share the existing 20,000-character/six-pair history budget. Very large histories use bounded batches, up to 12 compression requests; inputs beyond those limits fail explicitly. Real-model summary fidelity remains unverified.
- Conversation state is in memory only. Changing documents clears context/history; closing the diagram workbench ends its conversation. Summarized raw turns are replaced by their successful summary. Reference files themselves are still length-limited, not semantically compressed.
- The historical **494-item native acceptance matrix remains incomplete: 378 passed, 3 partial/unresolved, 104 tool-limited, and 9 unsupported**. APP-10, FILE-01, and C07 remain unresolved. Historical Linux WebKit automation timeouts are not claimed fixed. See the [acceptance matrix](../v0.11.0-deep-acceptance.md), [coverage audit](../v0.11.0-acceptance-audit.md), and [prior release limits](v0.12.0.md).
- Windows/Linux installed-desktop smoke tests and production macOS acceptance remain outstanding. Passing browser checks or package builds does not promote those cases to passed.
- The dependency audit reports no critical entries after updating DOMPurify. Two low-severity production entries remain in KaTeX/Mermaid, alongside 12 development-toolchain entries (5 high, 7 moderate). The remaining production advisory requires existing prototype pollution; no applicable exploit chain was demonstrated. This is not a clean or exhaustive security audit.

## Downloads and signing

Successful jobs attach unsigned Windows x64 EXE/MSI and Linux x64 DEB/AppImage installers with SHA-256 manifests. This release remains a desktop preview.

Production macOS packaging requires the existing Developer ID Application configuration. If that identity is unavailable, no production DMG is produced. An isolated memory-only development app is not substituted for a production Keychain build.
