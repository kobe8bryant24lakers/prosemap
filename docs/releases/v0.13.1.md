# ProseMap v0.13.1

This desktop preview fixes unintended text loss when custom AI instructions produce an incomplete replacement document.

## Changes

- Custom instructions now return local edits matched against the original text. The application retains text outside those edits, including unmentioned sections, tables, diagrams, whitespace, and line endings. Missing, ambiguous, overlapping, or malformed edits are rejected as a whole.
- Truncated output and abnormal provider completion no longer become acceptable suggestions. The desktop client waits for the final text to arrive even when the native command finishes before channel delivery.
- Explicit deletions have a reviewable diff and remain undoable. Failed and cancelled edits do not enter conversation history.
- Keep routine code checks on pull requests and the main branch; run the full browser acceptance suite manually. Release packaging reuses completed validation and retains version, installer, signing, and checksum checks.

## Validation and limits

- The implementation passed **624 frontend logic tests**, **67 native Rust tests on macOS arm64**, and **150 focused Chromium/WebKit checks** (75 per browser, without retries or skips). TypeScript, ESLint, Rust formatting, and the production frontend build also passed. Release preparation reuses these results; it does not claim a fresh full acceptance run.
- Browser tests use synthetic documents and model responses. They cover long documents, selected ranges, exact saved bytes, undo/redo, invalid or partial edits, delayed delivery, cancellation, conversation history, and diagram generation. Live-provider instruction following and the originally reported document have not been revalidated. Models must follow the local-edit response format; invalid responses are rejected instead of overwriting the document. Semantic adherence still requires reviewing the diff.
- The historical **494-item native acceptance matrix remains incomplete: 378 passed, 3 partial/unresolved, 104 tool-limited, and 9 unsupported**. APP-10, FILE-01, and C07 remain unresolved. Windows/Linux installed-desktop smoke tests and production macOS acceptance remain outstanding. See the [acceptance matrix](../v0.11.0-deep-acceptance.md), [coverage audit](../v0.11.0-acceptance-audit.md), and [previous release limits](v0.13.0.md).
- Outgoing commits, metadata, and complete diffs are reviewed for privacy before publication. Raw local logs, screenshots, credentials, generated build files, and private audit details are excluded from source commits.

## Downloads and signing

Successful packaging jobs attach Windows x64 EXE/MSI and Linux x64 DEB/AppImage installers with SHA-256 manifests. Windows installers are unsigned. Available packages are determined by the attached assets, not by browser test results.

Production macOS packaging requires the existing Developer ID Application configuration. If it is unavailable, no production DMG is published; an isolated development build is not substituted for a production Keychain build.
