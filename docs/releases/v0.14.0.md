# ProseMap v0.14.0

This desktop preview simplifies the writing workspace with neutral surfaces, clearer controls, searchable files, and a more compact AI assistant.

## Changes

- Replace the green interface chrome with a restrained gray, white, and blue palette. Improve document typography, reading width, toolbar grouping, selected states, and keyboard focus. Diagram content and semantic diff colors keep their meaning.
- Search local Markdown files by name or relative path, see matching counts, and recover from empty results with one action. Escape clears an active search while preserving focus.
- Keep document identity and save status visible in compact layouts. Show pending save feedback and prevent repeated save requests; completing a write does not clear edits made while it was pending.
- Put AI instructions before conversation and reference details, keep model setup and generation visible in a fixed footer, and use a native action selector in shorter windows. Command/Control + Enter generates a suggestion; plain Enter adds a line and IME confirmation does not submit.
- Keep file navigation reachable in narrow browser views and stack editing and preview when needed. Preserve editor history and reading position when switching views, including WebKit.
- Document the shared interface tokens and behavior in the [interface guide](../../DESIGN.md).

## Validation and limits

- TypeScript, ESLint, the production frontend build, and 16 focused frontend logic checks passed during implementation. The final focused browser run passed **36 Chromium/WebKit checks** without failures, retries, or skips. These cover file search, pending and failed saves, compact AI actions, keyboard and IME behavior, narrow layouts, view switching, reading position, and modal focus. Earlier failed development runs are not counted as passing runs.
- Publication reuses that completed focused validation and runs the repository's PR code checks. It does not claim a fresh complete browser acceptance run or a native desktop retest. Browser checks use synthetic documents, model responses, and native IPC substitutes; live-provider quality and operating-system dialogs are not established by those checks.
- The historical **494-item native acceptance matrix remains incomplete: 378 passed, 3 partial/unresolved, 104 tool-limited, and 9 unsupported**. APP-10, FILE-01, and C07 remain unresolved. Windows/Linux installed-desktop smoke tests and production macOS acceptance remain outstanding. See the [acceptance matrix](../v0.11.0-deep-acceptance.md), [coverage audit](../v0.11.0-acceptance-audit.md), and [previous release limits](v0.13.1.md).
- Outgoing commits, their author/committer metadata, and complete diffs are reviewed for privacy before publication. Raw local screenshots, logs, generated build files, credentials, and private audit details are excluded from source commits.

## Downloads and signing

Successful packaging jobs attach Windows x64 EXE/MSI and Linux x64 DEB/AppImage installers with SHA-256 manifests. Windows installers are unsigned. Available packages are determined by the attached assets; passing browser checks or producing packages does not establish installed-desktop acceptance.

Production macOS packaging requires the existing Developer ID Application configuration. If it is unavailable, no production DMG is published. An isolated development build is not substituted for a production Keychain build.
